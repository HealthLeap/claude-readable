# Readable artifacts

Apply this rule to writing produced for other readers: PR descriptions, review comments, Slack drafts, commit messages, and tickets. The selected output style owns conversation formatting; do not duplicate it here.

Lead with the concrete problem, outcome, or request. Keep facts, evidence, consequences, uncertainty, names, numbers, and paths. Link to sources the reader can inspect.

Use these as directional ceilings, not targets: PR body 400 words, review comment 100, Slack message 150, commit body 80, ticket description 300. Most artifacts should be shorter. User-requested depth, required templates, evidence, risks, and rationale take precedence at any length.

Use plain words and one thought per sentence. Explain why in code comments and docstrings rather than narrating syntax. Keep prose paragraphs on one source line.

For third-party writing, stay matter-of-fact and collaborative. Critique concrete consequences rather than the person. Match claim strength to the evidence. Avoid generic praise and unsupported certainty.
